# Squash

Recompose the current feature branch into one or a few coherent, changelog-ready conventional commits. This is a history rewrite, so require a clean worktree and index, a named current branch, a known merge base and a verified base branch. Never squash main, the remote default, or another protected branch. If a PR/MR is identified, verify that it belongs to the current branch and use its actual base; otherwise use the requested base or confirm the remote default. Fetch before comparing the branch and its remote. Stop on an unknown base, absent merge base, unfinished Git operation, or ambiguous remote ownership. If the branch has fewer than two unique commits, explain that there is nothing to collapse.

Capture the original tip in a unique local recovery ref **before** rewriting; do not overwrite an existing recovery ref. Report its name and original commit, keep it after completion, and explain that recovery requires restoring the original tip with care for subsequent changes. Compare the complete net diff from the merge base through the branch tip with the original messages. The net diff, not intermediate WIP or reverted commits, determines what belongs in the final changelog. Preserve genuine human coauthor trailers and issue references when still applicable; never add agent self-attribution.

Prefer one commit. Split into a small number only for genuinely independent concerns; show which paths and, where needed, which hunks belong to each group. A shared file can require separate staged hunks; never claim path-based grouping is sufficient when concerns overlap. Ensure that the planned commits together reproduce the full original net diff, including deletions, renames, and binary files. Draft each subject with conventional type and optional scope, imperative wording, no trailing period and no more than 72 characters. Use concise bullet bodies grouped by topic when helpful; keep text readable in changelogs without breaking URLs or file paths. A breaking-change marker requires explicit user authorization. Present the proposed messages, grouping, original/new history relationship, recovery ref, and whether a push was requested; obtain confirmation before rewriting, including when the user requested `--push`.

Rewrite locally using the reviewed grouping. Do not disturb the worktree's content or lose commits unintentionally. Verify that the new net diff equals the original net diff, the index/worktree is clean, and the resulting commits and coauthor trailers match the approved plan. Run appropriate project checks. On mismatch or failed checks, stop and preserve the recovery ref; do not push. Report both original and rewritten tips and any remaining work.

**Local-only is the default.** If `--push` was explicitly requested and verification succeeded, recheck the remote tip and protections, then update only the authorized feature branch with lease protection tied to the observed remote state. Never rewrite the base or use unconditional force on rejection. If the remote changed, stop and ask before reconciling. After a successful push, use the matching [GitHub](../providers/github.md) or [GitLab](../providers/gitlab.md) reference to watch CI for the rewritten tip within a bounded wait. Report failed checks and log locations; a failed run cannot undo the rewrite. If no identifiable run appears, report that CI was not verified.
