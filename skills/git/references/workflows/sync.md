# Sync

Synchronize **both** the current branch and local main with their corresponding origin refs. This is a local workflow: do not push, rewrite protected refs, silently drop commits, switch the user's worktree, or move a branch checked out in another worktree from the wrong worktree. Identify the remote default branch first; use main when it exists and is the intended default, otherwise explain the detected default (such as master). Report each ref independently even if one cannot be updated.

1. Inspect the current branch, working and index changes, unfinished Git operations, linked worktrees and their checked-out branches, configured upstreams and origin. A detached HEAD is not a current branch: do not move it; still evaluate main safely and report why current-branch sync is skipped. Fetch origin and stop if fetching fails; stale tracking refs are not a valid basis for synchronization. Do not assume a local main or a matching remote ref exists.
2. For main, compare its tip with origin's matching main/default ref for ahead, behind, equal, or diverged state. When behind only, fast-forward it in its owning **clean** worktree; if that worktree is the current one, it can be updated there. When main is checked out in another worktree, perform the fast-forward only in that owning worktree after checking that worktree's index, tracked and untracked changes, operation state and permissions. If it is dirty or inaccessible, leave main untouched and report the owning worktree and required manual action. When main is not checked out anywhere, advance its ref only after verifying that doing so cannot invalidate a worktree or discard local commits. If main is ahead or diverged, do not reset or rebase it automatically; report the local-only commits and ask how to reconcile. If absent locally, request confirmation before creating it from the remote. Never force-update main or bypass branch protection.
3. For the current non-default branch, identify its configured upstream, or explicitly confirm whether origin has a corresponding branch. Compare tips and distinguish equal, behind only, ahead only, and diverged. Fast-forward a behind-only branch if its owning worktree is clean; leave ahead-only commits intact and report them without pushing. When diverged, show the unique commits on each side and ask whether to merge, rebase using the [intent-preserving rebase workflow](rebase.md), or stop. Never assume a rebase, hard reset, force push, or silent drop. If the upstream or remote branch is absent, report the missing relationship and ask before setting an upstream or creating a branch. On detached HEAD, skip this step and do not manufacture a branch.
4. If the current branch is main, treat the two requested targets as the same ref and update it at most once. Verify final tips, ahead/behind counts, index and worktree state in each location touched. Report main and current-branch outcomes separately (including skipped, blocked, or diverged), the fetch outcome, and every check or decision still needed. A dirty worktree blocks only the update it would affect; it does not excuse skipping the other ref's assessment.
