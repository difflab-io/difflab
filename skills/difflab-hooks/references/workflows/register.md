# `hooks register`

1. Resolve `<name>` matching `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$` and optional `[handler]`. When `<name>` or `[handler]` is omitted or unclear, inspect the active harness, environment variables, loaded skills, local `--help` output, and official documentation first. Present fitting choices alongside `default` (`Handler: default` saves built-in behavior so future runs do not prompt again) and ask the user.
2. Make sure that `~/.difflab` is the physical home store (not a symlink) and that `~/.difflab/hooks/<name>/HOOK.md` does not exist. If `HOOK.md` exists, stop and offer manual editing or another name instead of overwriting it.
3. Prefer MCP `scaffold({name:"hook-definition",cwd:"<absolute home>/.difflab",path:"hooks/<name>",filename:"HOOK.md"})`, or run `difflab templates scaffold hook-definition hooks/<name> HOOK.md --cwd <absolute home>/.difflab`. Do not pass `path:".difflab/hooks/<name>"` with `cwd=<home>`, which targets a repository store.
4. Read the scaffolded `HOOK.md` and fill `## Trigger`, `## Action` (`Handler`, `Requires`, `Receives`), and `## Instructions` using [difflab-writing-style](../../../difflab-writing-style/SKILL.md):
   - `on-request-worktree` with `Handler: default`: set `Receives` to `project_key, repo_slug, source_root, base_ref, branch_name, branch_slug, task_brief` and record creating `~/.difflab/worktrees/{{project_key}}/{{repo_slug}}/{{branch_slug}}` from `{{base_ref}}`, running `difflab init {{project_key}}`, and coordinating via native subagents.
   - `on-remote-delegation` with `Handler: default`: set `Receives` to `project_key, repo_origin, base_ref, branch_name, approved_files, automerge_rules, task_brief` and record delegating through the native background or remote capability of the active harness.
   - Custom handler: inspect current official documentation and CLI `--help` output for the chosen tool before writing concrete instructions.
5. Report `~/.difflab/hooks/<name>/HOOK.md`, trigger, and handler without executing the hook.
