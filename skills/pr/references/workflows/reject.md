# Request changes

Follow [review submission](review-submission.md) with a native request-changes disposition. Confirm the pending comments or overall reason make the request actionable; ask for a reason if neither exists. On GitHub, submit the authenticated user's pending review as a request for changes, with the user's supplied overall text when present. On GitLab, first verify that the current instance, project, and account support the native requested-changes review state for this operation. If not supported, stop without publishing notes or substituting a general comment, disapproval, or approval withdrawal. If supported, publish the user's draft notes with that state and verify it was recorded. Report any partial or failed operation accurately. Do not mark the request ready or merge it.
