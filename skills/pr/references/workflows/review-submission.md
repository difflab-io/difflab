# Submit a review disposition

Shared guidance for [approve](approve.md), [reject](reject.md), and [comment](comment.md). This does not change the PR/MR draft/ready state and does not generate a review document.

Resolve the explicit request or unique open request for the current branch. Confirm repository, URL, authenticated reviewer, and desired disposition. Fetch only that account's pending inline review or draft notes and show their count and target. Never submit, edit, or discard another reviewer's pending content. If no pending inline comments exist, explain that this action will submit only the requested disposition and optional overall comment. If the user intended to publish specific inline comments that are absent, stop and ask. Do not copy comments from a local artifact without explicit authorization and verified anchors.

Use the user-supplied overall comment verbatim, if any. Do not synthesize a summary of the inline notes. Omit the overall comment when optional; if an API requires text, use a minimal neutral description of the disposition rather than pretending the user wrote it. For a request for changes that requires a reason and has no pending notes or user message, ask for actionable feedback. Confirm the disposition and any irreversible publication before submitting. Verify the resulting review state and note count. If publishing and setting a disposition are separate operations, report partial success accurately; never retry in a way that duplicates published notes. Use [GitHub](../github.md) or [GitLab](../gitlab.md) provider semantics, not an approximate replacement.
