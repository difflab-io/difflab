# GitLab capabilities

Use existing authenticated GitLab forge capabilities for merge request metadata, draft creation, ready transition, current user's draft notes, review submission, approval, merge, and pipelines. Confirm the project path, MR internal identifier, authentication, permissions, tier, and project rules; do not infer state solely from a title prefix when structured draft status is available.

Draft notes belong to the authenticated user. Bulk publishing those notes may accept a summary note and reviewer state; an approval is a distinct action and may fail under project approval rules. A comment-only submission publishes current user's draft notes and may include the supplied summary without approving. For an approval, publish the draft notes first, then apply approval only if both actions are supported and authorized; report partial success if approval fails. If the user has no pending notes, an approval or general comment can be submitted using supported operations without inventing inline notes. Preserve an explicitly supplied overall comment; omit it when optional and absent.

Current GitLab documentation describes a `requested_changes` review state on draft-note bulk publication, but availability and blocking behavior vary by version, tier, and project settings. Before rejecting, verify that this instance and the authenticated account support the requested native change-request state and can publish the current user's pending notes with it. If unsupported, stop without publishing notes or replacing the request with an ordinary comment or a disapproval. If the API needs a reason and the user supplied none, ask for one. Do not assert a change-request state from a mere note.

After merging, resolve the resulting base branch SHA and match base-branch pipelines to that SHA and ref. Merge-request and merged-results pipelines are not necessarily post-merge pipelines. Surface pipeline URLs and failing job logs, and distinguish no configured pipeline from one that has not appeared yet. See [merge](../workflows/merge.md).

Official references: [draft notes API](https://docs.gitlab.com/api/draft_notes/), [merge request reviews](https://docs.gitlab.com/user/project/merge_requests/reviews/), and [pipelines API](https://docs.gitlab.com/api/pipelines/). Recheck current instance documentation before using version-dependent operations.
