# `poc new [request]`

1. Treat a short supplied name as the intended branch slug: `poc new auth: compare two login flows` uses `poc/auth`; `poc new auth` retains `auth` but asks for an experiment before running `init`. A multiword natural-language request without a `name:` separator is the experiment, not a first-word name. Require a concrete question or experiment from the user's prompt. Ask for scope when it is not clear whether they want an alternative implementation, a radical refactor, or a from-scratch sandbox. Never infer permission to remove the existing application from a vague request.
2. Run the `init` workflow first. If already on a PoC branch, validate its merge gate, clean tree, README `base_commit`, and branch/intent match; preserve its existing README. If creating one, prefer the explicit safe name; otherwise derive a short name from the experiment or ask on collision. Never silently rename an explicit request. Stop if `init` stops. Do not start the experiment on main or an arbitrary feature branch.
3. Implement only what answers the question. Prefer a small runnable slice with an explicit comparison, rather than production polish. Alternative implementations may coexist in isolated modules or commits; do not replace existing work without the user's direction. A from-scratch PoC may remove large parts of the codebase **only on the verified PoC branch** and only when explicitly requested; confirm scope before any broad deletion, check status again, and never run a destructive command in another worktree/branch.
4. Update branch-local `README.md`: purpose, approach(es), instructions to reproduce, actual test results and observations, learnings and open questions. Retain the original full `base_commit` frontmatter unchanged; never state unrun checks passed. Compare to the captured base using `git diff <base_commit> HEAD` when needed. Keep notes short and useful to someone examining the frozen tag later.
5. Run the narrowest meaningful checks. Report changed files, branch, exact base SHA, outcomes, skipped checks, and next step (`poc freeze` when ready). No merging, production release, force push, or implicit commit/push.
