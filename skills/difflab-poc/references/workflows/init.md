# `poc init [name]`

Read [PoC code standards](../poc-code-standards.md) before acting.

1. Confirm the repository root, GitHub/GitLab `origin`, current branch, and clean worktree. Reject detached HEAD. Accept a safe lowercase name for `poc/<name>`. If already on a PoC branch and no name was given, use that branch. Otherwise ask for a name. Do not require a forge merge gate or change remote rules.
2. If already on the named PoC branch, keep its PoC README and original base. Read the full `base_commit` SHA from frontmatter before repairing missing README replacement or runnable-task guidance. Make sure that it exists and is an ancestor of HEAD. If it is missing or invalid, ask for the original base. Never substitute today's `origin/main`. Once the original base is verified, repair missing deliverables within the requested experiment without discarding work. If the user names another existing local or remote PoC branch, ask how to recover it; do not recreate or switch silently.
3. For a new branch, run `git fetch origin main`. Save the full `refs/remotes/origin/main` commit SHA before branching. Create `poc/<name>` at that SHA with `git switch --no-track -c`. Do not branch from local main or HEAD. If creation fails, stop.
4. Scaffold `poc-readme` to `POC-README.md` with MCP at the checkout root, or use `difflab templates scaffold poc-readme . POC-README.md --cwd <absolute-root>` when MCP is unavailable. If that temporary name exists, stop. Fill `base_commit` with the saved SHA. On this PoC branch only, replace `README.md` and remove the temporary file. If replacement fails, keep the branch and report how to recover it. Fill the purpose, setup, module/alternative map, and mise task instructions; mark unimplemented results pending. Provide applicable build/test tasks and a named run task for each implemented prototype. Do not discard dirty work.
5. Report the branch, base SHA, README path and changes. Use `git diff <base_commit> HEAD` for a stable comparison. Do not commit or push without separate authorization.
