# `poc init [name]`

1. Resolve the absolute repository root, the GitHub/GitLab `origin`, and the requested branch name (`poc/<lowercase-hyphenated-name>`). Accept only a simple, safe slug; if unnamed and the current branch is `poc/*`, use it. Otherwise ask for the name. Do not operate from detached HEAD or a dirty worktree; report changes the user needs to save. Ensure `origin/main` exists. **Before branch creation or reuse**, follow `../merge-gate.md`; stop and ask to enable enforcement if it is not proven effective. Do not treat `go` or `poc init` as permission to change remote rules.
2. If already on the intended `poc/*` branch, keep it as-is; require an existing PoC README with a full `base_commit` SHA in frontmatter. Verify `git cat-file -e <base_commit>^{commit}` and `git merge-base --is-ancestor <base_commit> HEAD`; if absent or inconsistent, ask for the original base (do not replace it with the current main tip). Do not replace or re-scaffold an existing README. If already on a different PoC branch, stop rather than silently switching experiments. If the named branch exists elsewhere locally or on origin, stop and ask whether to switch/recover; do not recreate it.
3. On a non-PoC branch with a clean tree, run `git fetch origin main` and capture the full `git rev-parse refs/remotes/origin/main` SHA. Check it is a commit. Only then create `poc/<name>` at exactly that SHA (`git switch --no-track -c poc/<name> <sha>`); do not use an out-of-date local main or branch from HEAD. If the branch command fails, leave the checkout untouched.
4. Scaffold `poc-readme` into a new `POC-README.md` at the checkout root using MCP `{name:"poc-readme",cwd:<absolute checkout root>,path:".",filename:"POC-README.md"}`; fill the frontmatter's `base_commit` with that SHA and the other fields with known intent or honest TBD notes. Replace **only** this branch's `README.md` with the filled template and remove the temporary file. If a staging filename already exists, stop; never overwrite it. If scaffolding or README replacement fails, retain the branch and report exact recovery steps, not a false success. Record `git diff <base_commit> HEAD` as the stable diff command; `origin/main` may move later.
5. Report branch, base SHA, README path, gate evidence, and uncommitted changes. Never merge the branch or commit/push without separate authorization.
