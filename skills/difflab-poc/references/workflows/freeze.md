# `poc freeze`

Freeze means **preserve a commit as an annotated tag, then delete both local and origin branches**. Do not merge. The tag name is exactly the branch name, `poc/<name>`; disambiguate every Git reference with `refs/tags/` or `refs/heads/`.

1. Require current local branch `poc/<name>` and a clean tree (no staged, unstaged, or untracked work); ask the user to save any outstanding work before proceeding. Read the PoC README and validate its original full `base_commit` is an ancestor of `HEAD`; require a meaningful purpose and learnings. Resolve `HEAD` to a full SHA. Fetch the remote branch and tags. Require `refs/remotes/origin/poc/<name>` and the actual remote `refs/heads/poc/<name>` to match HEAD; if missing, behind, or divergent, stop and ask how to publish/reconcile, never silently push or discard changes.
2. Check that neither a local `refs/tags/poc/<name>` nor remote tag exists. If an annotated tag already exists, verify its peeled commit equals HEAD and the remote tag agrees; if not, stop instead of overwriting. For a new tag, create an annotated `refs/tags/poc/<name>` at HEAD with a message naming the PoC and base commit. Push **only** that tag (`refs/tags/poc/<name>:refs/tags/poc/<name>`). Check the remote's peeled tag SHA (and local annotation) matches HEAD; if push or verification fails, keep both branches and report the existing tag state. Never force-update a tag.
3. After remote tag verification, explicitly ask the user to confirm deletion of **both** `refs/heads/poc/<name>` locally and on origin. If confirmation is declined, keep both branches and the verified tag. On confirmation, check that the remote branch still points to the tagged HEAD. Switch to an existing safe non-PoC branch (normally `main`); if switching is unsafe or unavailable, stop without deleting. Delete the remote branch conditionally with a lease against the verified SHA to protect against concurrent pushes; verify its absence. Only after that verification, delete the local branch (ordinary `-d` may refuse because a PoC is intentionally unmerged; use `-D` only now, after tag verification, remote deletion, and explicit confirmation). Never delete main or another branch.
4. On any failure, stop, keep the tag, preserve whatever branch refs remain, and give the user the exact tag/branch SHAs and recovery steps. Reruns may resume only after confirming the existing annotated tag points to the same intended commit; never reassign an existing tag. Report tag, base SHA, preserved commit, deletion results, and `git diff <base_commit> refs/tags/poc/<name>` for historical comparison.
