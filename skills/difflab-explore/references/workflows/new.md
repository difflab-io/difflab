# `explore new`

Read `../research-standards.md` before researching. This is research-only work, not code implementation.

1. Confirm absolute repository root and valid initialized `.difflab` project-store symlink. Resolve the topic from the user's request; ask only if the question or constraints cannot be inferred. Derive a short safe lowercase hyphenated slug; verify `.difflab/explore/<slug>/` does not already exist, including dangling links. On collision, stop and ask whether to update that exploration or choose another name. Do not quietly append a suffix or overwrite anything. Reject paths outside `.difflab/explore/` and symlinks under the target.
2. Determine whether the user wants research only or distinct proposals; if unspecified, ask once. Confirm scope, priorities and success criteria if ambiguous. Outline independent research angles (at least codebase prior art and relevant external ecosystem for a technical choice). Delegate independent angles by effort/tier as described in research standards, when beneficial; otherwise research directly. Require each handoff to include fetched primary sources, precise URLs, version/commit and access date, and unknowns. Verify sources yourself.
3. Scaffold `exploration-summary` as `.difflab/explore/<slug>/SUMMARY.md` and `exploration-research` as `.difflab/explore/<slug>/research/<angle>.md` through MCP `scaffold` (absolute `cwd`, relative `path`, single filename); use unique safe angle slugs and refuse existing files. Scaffold `exploration-proposal` into `proposals/<approach>.md` **only** if requested. Scaffolding is exclusive and does not render placeholders: fill the files after research, checking no placeholder remains. If research fails, leave the in-progress summary clearly marked and report the incomplete files; never present it as completed research.
4. Read and synthesize all verified research notes. Summary links each note, compares distinct approaches when relevant, and may explicitly say no recommendation. Each optional proposal is a meaningfully different approach with evidence, integration shape, and honest trade-offs. Do not write application code or implementation task lists.
5. Verify generated files and inline source links against fetched pages, paths inside the project store, and no outstanding placeholders. Report exact paths, proposal choice, evidence freshness, unknowns and any failed fetches. Do not commit.

Example: `explore new whether an embedded search index fits our CLI` → `.difflab/explore/embedded-search-index/SUMMARY.md` and `research/*.md`; `proposals/*.md` is optional.
