# `explore update`

Read `../research-standards.md` first. Updates are research-only; no code changes or commits.

1. Confirm absolute repository root and initialized `.difflab` project-store symlink. Identify exactly one existing `.difflab/explore/<slug>/` from the user's name/context; ask if ambiguous or missing. A revisit without feedback is valid when target and scope are clear. Record the user's verbatim feedback **or** an explicit statement of the revisit request, changed scope, and why it was requested; never invent feedback. Clarify whether proposals should be created/updated; existing proposals remain live unless explicitly retired.
2. Before any live changes, acquire an exclusive per-exploration update lock (`mkdir` with failure on existing `.update-lock`). If already locked or a prior incomplete revision exists, stop and resolve ownership/recovery; never delete someone else's lock. Under the lock, inventory **every** live regular file and directory under this exploration, not just `SUMMARY.md`, `research/`, and `proposals/`; exclude only `revisions/`, the owned lock, and staging paths. Reject symlinks, special files, unreadable paths, and paths escaping the physical project store. Verify `SUMMARY.md` and research notes are readable. Do not follow symlinks, and do not modify any existing revision.
3. Inspect _all_ numbered `revisions/<N>/` directories, including incomplete ones, and use `max(N)+1` (do not fill gaps). Reserve `revisions/<N>/` **exclusively** with atomic directory creation; on collision, stop/re-inventory while holding the lock, never reuse it. Copy all inventoried live artifacts, preserving relative paths, into `revisions/<N>/artifacts/` without recursion into `revisions/`. Write `revisions/<N>/FEEDBACK.md` with the verbatim feedback or explicit no-feedback revisit request, date and scope. Keep `FEEDBACK.md` outside `artifacts/` so a live file with the same name remains preserved too. Verify the copied manifest against the inventory (paths and file bytes/checksums); write a final completion marker only after _all_ files and feedback are durable. Do not edit live files if any operation fails. Leave an incomplete reserved revision for investigation; do not reuse or erase it. Release only the lock owned by this run.
4. Re-fetch relevant primary sources and check changed versions, maintenance/licensing and new prior art. Distinguish unchanged old evidence from new/withdrawn evidence. Build the **entire** updated live artifact set in a private staging area under this exploration (not under `revisions/`), using scaffold for any _new_ research/proposal documents with exclusive filenames; never point scaffold at an existing file. Verify citations and references, then publish only after the snapshot is complete. Replace existing live files via same-filesystem temporary-file + atomic rename; if publication fails midway, restore **all** affected live files from the verified snapshot, remove newly created files, and report failure. If interrupted before rollback, stop future updates and recover live artifacts from the last complete revision before proceeding. Do not treat per-file renames as an atomic multi-file transaction; never claim completion until the full set verifies. Preserve earlier revisions unchanged, and do not silently delete old live research or proposals.
5. Update live `SUMMARY.md` with date, revision path, request, what evidence changed and which prior claims remain unverified. Research-only revisits do not force proposals or a recommendation. Check that no scaffold placeholders remain and all outputs remain under `.difflab/explore/<slug>/`. Release the owned update lock after verification; report paths, snapshot number, feedback handling, changed evidence and limitations.

Safety rehearsal (use a disposable initialized project store; never test against a user's live exploration): start with a research-only exploration containing `SUMMARY.md`, two research notes and an extra live artifact. Revisit once with explicit feedback and optional proposals, then again without feedback and without proposals. Confirm each revision's `artifacts/` has byte-identical copies of **all** files that were live immediately before that revisit; `FEEDBACK.md` contains the exact feedback or no-feedback request; earlier revisions stay unchanged. Force a revision-ID collision and a failed copy/unreadable note, and verify that neither changes live bytes. An existing `revisions/3/` causes allocation of 4 even if 2 is missing; a collision creating 4 must not modify `SUMMARY.md`. A failed copy leaves 4 incomplete for investigation and publishes nothing.
