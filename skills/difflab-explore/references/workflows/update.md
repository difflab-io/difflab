# `explore update`

Read `../research-standards.md`. Change research files only.

1. Select one `.difflab/explore/<slug>/`. Ask if the target or scope is unclear. Record the user's exact feedback. For a revisit without feedback, record the request, changed scope, reason, and date instead. Ask whether to change proposals; otherwise keep them.
2. Create an exclusive `.update-lock` directory before reading live files. If it exists, stop. Keep the lock until publication and final verification finish. Resolve the physical project store. Reject a symlinked `revisions/` directory, any symlink below it, and any revision path outside the store. Reject symlinks, special files, or unreadable live files. If any earlier revision is incomplete, stop and ask how to recover it.
3. Under the lock, list every live file and directory. Exclude only `revisions/`, `.update-lock`, and this run's staging files. Set `N` to one more than the highest numbered revision; never fill gaps. Create `revisions/N/` exclusively. If creation collides, stop and recount under the lock. Copy every live file and directory to `revisions/N/artifacts/` with its relative path. Write `revisions/N/FEEDBACK.md` with the exact feedback or revisit request, date, and scope. Compare the copied paths and checksums with the live inventory. Write a completion marker only after the copy and feedback are complete. If copying fails, leave the incomplete revision for recovery and do not edit live files.
4. Fetch new primary sources and compare them with earlier evidence. Build all changed files, including `SUMMARY.md`, in private staging under this exploration. Use MCP `scaffold` only for new files with unused names. Verify source links and remove placeholders. After the snapshot is complete, publish existing files with same-filesystem temporary files and atomic renames. If publication fails, restore every affected file from the snapshot and remove newly published files. If the process stops before rollback, require recovery before another update. Do not delete old research or proposals without an explicit request.
5. Make sure that the live summary records the date, revision, request, changed evidence, and unknowns. Make sure that every output stays inside `.difflab/explore/<slug>/`. Release only this run's lock after these checks or after a safe failure and rollback. Report the revision, changed files, and limits. Per-file renames do not make the whole update atomic.

Rehearse in a disposable store, not the user's live exploration. Test feedback and no-feedback revisits, extra files, gaps in revision numbers, collisions, and failed copies. A failure must leave live files unchanged. Earlier revisions must keep their original bytes.
